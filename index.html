    Técnicas de Programação II: Padrões de Projeto para Sistemas Embarcados em C++¶

    Bem-vindo(a)! Este curso continua o C++ do Zero. Lá você aprendeu a linguagem; aqui você vai usá-la para o que ela faz de melhor fora de um PC: controlar hardware, e no tempo certo. Tudo roda num ESP32 simulado no Wokwi, direto no navegador, sem precisar comprar placa nenhuma.

    Para quem é este curso¶

    Para quem já escreveu uma classe em C++, mesmo que sem muita segurança. Se você fez o C++ do Zero, está pronto. Se veio por outro caminho (sabe C, mas class, construtor e referência ainda soam estranhos), comece pela página de Nivelamento: ela diz exatamente o que revisar antes da primeira aula.

    Na Engenharia Elétrica do IFPB, a disciplina é uma optativa cursada depois de Sistemas Microcontrolados: ADC, PWM, interrupções e I2C você já fez funcionar lá. Aqui eles voltam como cenário, e a pergunta passa a ser como organizar o firmware para que ele seja testável, trocável e cumpra prazos. Mesmo assim, cada peça nova (LED, botão, potenciômetro, display) é apresentada na hora em que aparece, com o mínimo de eletrônica necessário para o código fazer sentido.

    A ideia do curso em uma frase¶

    Cada aula resolve um problema de projeto de firmware com um padrão de projeto e o C++ que o sustenta, e o caminho termina em sistemas de tempo real: programas que precisam responder não só certo, mas a tempo. A classe da aula anterior quase sempre é a peça da aula seguinte:

    Led  ──►  Botao  ──►  Temporizador  ──►  Semaforo (máquina de estados)
  ──►  Hardware Proxy  ──►  Adapter de sensor  ──►  interfaces e dublês de teste  ──►  interrupções
  ──►  Command  ──►  Observer e Strategy  ──►  executivo cíclico  ──►  tarefa periódica (FreeRTOS)
  ──►  filas  ──►  mutex e RAII  ──►  Active Object  ──►  watchdog e modo degradado  ──►  MQTT

    Dois lugares para rodar código, de propósito

    Quase todo assunto é praticado de duas formas:

    • Sem placa (exercícios ex): a lógica da classe roda num compilador online, com testes automáticos. Um arduino_falso.h faz o papel do hardware: ele "lembra" o que foi escrito em cada pino e deixa o teste avançar o relógio.
    • No Wokwi (exercícios wk): a mesma classe controla um LED, um servo ou um display de verdade (simulados).

    Separar a lógica do hardware não é só conveniência didática: é a técnica que os profissionais usam para testar firmware, e o projeto final exige isso.

    Como o curso é organizado¶

    São 14 semanas, com duas aulas de 90 minutos em laboratório, divididas em 5 unidades:

    1. Objetos que controlam pinos (capítulos 1–4): classes para LED e botão, tempo sem delay(), composição e máquinas de estados.
    2. Perto do metal: padrões de acesso ao hardware (capítulos 5–9): bits em C++, registradores tipados, Hardware Proxy, Adapter de sensor, interfaces e dublês de teste, interrupções.
    3. Padrões de comportamento e tempo real (capítulos 10–13): memória sem heap, Command, Observer, Strategy, prazo, latência e jitter, executivo cíclico, tarefas do FreeRTOS e tarefas periódicas.
    4. Padrões de concorrência (capítulos 14–17): filas e interrupções diferidas, mutex e RAII, inversão de prioridade, Active Object e máquinas de estados hierárquicas, I2C como recurso compartilhado.
    5. Sistemas robustos e conectados (capítulos 18–19): SPI e padrões de robustez (watchdog, timeouts, modo degradado), Wi-Fi e MQTT sem perder prazo.

    Capítulo é diferente de aula

    Os capítulos são numerados de 1 a 19. A maioria ocupa uma aula; os capítulos 8, 11, 13 e 16, mais densos, ocupam duas. As duas avaliações, o laboratório do projeto e as apresentações completam os 28 encontros, mas não têm capítulo.

    Como estudar¶

    1. Leia o capítulo da semana. Ele tem os mesmos exemplos da aula, com mais contexto e uma seção de "Erros comuns".
    2. Resolva a lista do capítulo: primeiro os ex (sem placa), depois os wk (no Wokwi).
    3. Travou? Consulte Erros comuns e a Pinagem antes de qualquer coisa: metade dos problemas no Wokwi é um fio no pino errado.
    4. Quer outra explicação para o mesmo assunto? O apêndice de referências diz qual livro ou documentação consultar para cada unidade.
